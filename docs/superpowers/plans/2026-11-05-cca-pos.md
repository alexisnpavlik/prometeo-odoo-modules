# Cuenta corriente desde el POS — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vender a cuenta corriente y cobrar cuotas desde el POS del kiosco, con el stock moviéndose una sola vez y la caja cuadrando.

**Architecture:** Módulo puente nuevo `customer_checking_account_pos` (depende de `customer_checking_account` + `point_of_sale`, `auto_install`). El servidor engancha `pos.order._process_order` (después de `super()`, donde las excepciones sí se propagan) y crea `cca.withdrawal` / `cca.payment` en la misma transacción del sync. El módulo base **no se modifica**: el puente sobreescribe `_cca_create_sale_order` y `_cca_return_picking` para que un retiro con `pos_order_id` no toque stock. El frontend son patches OWL sobre `PaymentScreen`, `PosOrder` y el ticket.

**Tech Stack:** Odoo 18, Python, OWL (POS), PostgreSQL. Tests con `odoo.addons.point_of_sale.tests.common.TestPoSCommon`.

**Spec:** `docs/superpowers/specs/2026-11-05-cca-pos-design.md`

## Global Constraints

- Odoo 18.0; versión del módulo `18.0.1.0.0`; `license` `LGPL-3`; `author` `Alexis Medina`; layout y estilo según el skill `odoo-prometeo-modules` (un archivo por modelo, docstring en español en cada método, `_("texto %s", arg)`).
- Assets del POS en `point_of_sale._assets_pos`; patches con `@web/core/utils/patch`.
- El módulo base `customer_checking_account` no se edita (sus 78 tests deben seguir en verde).
- Toda escritura en modelos `cca.` desde el sync del POS va con `sudo()`: el cajero no está en `group_cca_user`.
- Retiro y pedido se crean en la misma transacción: cualquier error → `UserError` que vuelve el pedido a borrador en el POS.
- Ajustes: sección nueva `<block title="Punto de venta">` dentro del `<app>` existente del módulo base (memoria "Ajustes en app propia").
- Tests: base scratch `cca_test` (hoy sin `point_of_sale`; el `-i` lo instala). Nunca `prod`. Verificación visual en `kiosco`.
- Comando de tests (contenedor `odoo-odoo-1`, docker sin sudo):
  `docker exec odoo-odoo-1 odoo -d cca_test -i customer_checking_account_pos --test-enable --test-tags /customer_checking_account_pos --stop-after-init --no-http --workers 0`
  (con `-u` en vez de `-i` a partir de la segunda corrida). Tras cada `-i/-u`: `docker restart odoo-odoo-1`.
- Ningún push a `main`: todo entra por PR desde `feat/cca-pos`.

## Review Focus

1. **Cajero sin `group_cca_user`** sincroniza una venta a cuenta corriente → tiene que funcionar (sudo). Test en Task 3.
2. **Pedido con descuento de línea / promo** → la deuda del retiro es igual al `amount_total` del pedido (precio con IVA y descuento). Test en Task 3.
3. **Pedido que se re-sincroniza** (mismo `uuid` enviado dos veces, pasa cuando el POS reintenta) → no crea un segundo retiro ni un segundo pago. Test en Task 3 y Task 4.
4. **Pago con el producto que supera la deuda** → el sobrante queda como saldo a favor, no falla. Test en Task 4.
5. **Reembolso de una venta a cuenta corriente con pagos imputados** → el reembolso falla con el mensaje de `action_cancel`, no deja el retiro a medio cancelar. Test en Task 5.
